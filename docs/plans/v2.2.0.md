# v2.2.0 — «Dyatel работает»: трекер / tracker

Цель: продукт работает в проде end-to-end (Tiny как проксер на glacier),
закрыты дыры RFC, CLI получил PAT-токены, панель причёсана.

## Фаза 1 — код (ветка `feat/v2.2.0-api`)

- [x] PAT-токены: `POST/GET/DELETE /api/v1/tokens`, SHA-256 digest,
      `dyatelctl tokens create|list|rm`
- [x] `PATCH /api/v1/hosts/{id}` (endpoint, keepalive, consumer) +
      `dyatelctl hosts edit`
- [x] `GET /api/v1/users?q=` (каталог для приглашений)
- [x] `GET /api/v1/events?limit=` (свой след; админу — весь)
- [x] `POST /api/v1/reconcile` + `dyatelctl reconcile`
- [x] Панель: вкладки tokens/activity, приглашение из каталога,
      онбординг-команды, admin-only status
- [x] Тесты: lifecycle, изоляция токенов, PATCH-инварианты, scoping
      событий (зелёные дважды подряд против `dyatel_smoke`)
- [x] RFC: матрица прав приведена к коду (форварды публикует owner)
- [x] Документация: `docs/{en,ru}/attach-your-machine.md`, README
- [x] Независимое ревью (Antigravity): найден и исправлен баг —
      смена consumer не сбрасывала его ключ/IP на шлюзе
